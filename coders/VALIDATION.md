# MVP validation — 2026-10-28

검증 환경: Linux amd64, Node.js 26, PostgreSQL 18, Redis 8.
실제 Coders 운영 리소스 검증과 로컬 검증을 구분합니다.

## 통과한 로컬 검증

- 프론트 TypeScript 검사·Vite 빌드, 정적 프론트 아티팩트 생성.
- 서버 TypeScript 빌드.
- 전체 프론트 테스트: 31개 파일, 440개 테스트 통과.
- Coders 신원·역할·라우팅, JWT 가드, 협업 인증, 권한 캐시 관련 서버 테스트:
  5개 스위트, 35개 테스트 통과.
- 빈 DB에서 일반 멤버 선행 접속 거부, 검증된 owner의 원자적 초기 관리자 생성,
  이후 멤버의 일반 권한 등록.
- 잘못된 역할·누락된 신원·다른 리소스 접근·로컬 비밀번호 로그인·설정 우회 거부.
- 비공개 공간 접근 거부, reader의 쓰기 거부, writer 권한 부여와 철회 즉시 반영.
- 문서 생성, DB 첨부파일 업로드·다운로드·HTTP 범위 다운로드.
- 서로 다른 두 사용자 Yjs 편집 동기화, 연결 종료 후 재접속·DB 복원.
- 앱 프로세스 재시작 후 저장된 문서·첨부파일 유지.
- Chromium의 두 사용자 편집, 새로고침 복원, 두 사용자 알림 소켓 인증,
  소스 링크 표시, 브라우저 런타임 예외 없음.
- 실제 로컬 Core SDK를 제공한 브라우저에서 402 응답 후 같은 멱등성 키로
  재시도하고 원래 요청을 완료하는 흐름 확인. SDK 구현은 포크에 포함하지 않습니다.
- Core와 같은 script/connect/img/worker CSP 제한을 적용한 브라우저에서도
  기본 문서·협업·SDK 재시도 검증 통과.
- SDK 전송 계층의 multipart·바이너리·상태 코드·준비 중 재시도·네트워크 응답 불명
  처리 및 취소 시 확인 UI 정리 테스트.
- 최종 구성의 배포용 이미지로 별도 빈 DB에서 통합 검증.
  이미지 비압축 크기 약 169 MiB, UID/GID 65534, 읽기 전용 루트,
  `/tmp` 64 MiB, 추가 볼륨 없음.
- Enterprise 소스 디렉토리·프론트 import 부재 검사.
- 실제 Core `Manifest` 모델로 `coders.json` 검증 통과. 정적 프론트는
  189파일·7,170,391바이트로 기본 256파일·10MiB 제한 이내입니다.

Node.js 26의 전역 Web Storage와 jsdom 테스트 환경 충돌을 피하기 위해
프론트 테스트에 `NODE_OPTIONS=--no-experimental-webstorage`를 사용했습니다.

## 전체 서버 테스트의 제한

전체 서버 테스트 실행 결과는 55개 스위트 통과, 16개 스위트 실패입니다.
실패는 의존성 제공자가 빠진 원본의 Nest 테스트 스캐폴딩에서 발생했습니다.
전체 서버 테스트가 통과한 것으로 표시하지 않습니다.

## 아직 별도로 확인해야 하는 운영 조건

최초 GitHub-hosted 빌드·GHCR 공개 이미지·provenance 게시를 확인했습니다.
실제 Coders PostgreSQL의 확장/DDL 권한, Redis ACL, 엔드포인트 중계,
300초 연결 회전, 플랫폼의 메시지·본문·메모리·동시 연결 한도는
실제 Coders 리소스에서 최종 확인해야 합니다.

프로세스 강제 종료 직전의 미저장 편집까지 무손실임을 보장하는 검증은 아닙니다.
Core 인프라 비용과 운영 DB의 보관·백업 정책은 별도로 관리해야 합니다.
